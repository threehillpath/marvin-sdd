# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## What this repo is

A Claude Code plugin that implements a structured architecture-to-implementation workflow using GitHub issues and Projects v2 boards. It contains no executable code — only skill definitions (markdown instruction files) consumed by the Claude Code plugin system.

## Repository structure

```
.claude-plugin/plugin.json     ← Plugin metadata
skills/
  SHARED/                      ← Governance files referenced by all skills
    CONFIG.md                  ← Template for per-project config file
    NAMING.md                  ← Plan number and branch naming conventions
    LABELS.md                  ← GitHub label rules
    RENDERING.md               ← Markdown output guidance
  <skill-name>/
    SKILL.md                   ← Skill instructions (the authoritative prompt)
    SUPPLEMENTS/               ← Supporting templates, conventions, strategies
```

## Workflow and skill ordering

Skills must be run in order within a plan:

```
/arch-plan → /impl-plan → /phase-split → /start-impl →
    /implement-phase (once per phase) → /finish-impl
```

`/move-issue` and `/finish-phase` can be used at any point alongside the main flow.

## Plan numbering and naming

Every plan traces back to a source GitHub issue number, which becomes the PLAN number (zero-padded to 5 digits):

- Source issue #42 → `PLAN-00042`
- Arch plan issue title: `[PLAN-00042-ARCH] Title`
- Impl plan issue title: `[PLAN-00042] Title`
- Phase issue titles: `[PLAN-00042-1] Title`, `[PLAN-00042-2] Title`, …
- Implementation branch: `feature/plan-00042`
- Phase branches: `feature/plan-00042-1`, `feature/plan-00042-2`, …

Edge case: if an arch plan spawns multiple impl plans, suffix them `[PLAN-00042-A]`, `[PLAN-00042-B]`, with branches `feature/plan-00042-a`, etc.

## Per-project config

Skills read `.claude/plan-workflow-config.md` in the consuming project (not this repo). This file is generated by `/configure-plan-plugin` and contains the GitHub repo, Projects v2 project ID, status field ID, status option IDs, and test commands. `skills/SHARED/CONFIG.md` is the template for that file.

## How skills work

Each `SKILL.md` defines:
- Which Claude model to use (opus for planning, sonnet for implementation, haiku for board ops)
- Which tools are allowed
- Step-by-step instructions including `gh` CLI commands and `jq` expressions

Skills reference SHARED files for naming, labels, config, and rendering guidance. Supplements provide templates and deeper guidance but are not the primary instructions.

## Key design rules

- **Plans specify "what", not "how"** — implementation is for Claude to discover from code context
- **TDD is mandatory** for backend and testable frontend logic (reducers, utilities, validation); exempt only for rendered UI components
- **Phases are independently mergeable** — each phase gets its own branch and PR to the impl branch; the impl branch PRs to main
- **`/implement-phase` spawns a sub-agent** with `isolation: "worktree"` for autonomous TDD loop execution
- **Board state is authoritative** — every skill moves issues through Backlog → Ready → In Progress → In Review → Done

## Requirements (for consuming projects)

- `gh` CLI authenticated with repo and project access
- GitHub Projects v2 board (classic projects not supported)
- `jq` for JSON parsing in board management commands
- `glow` (optional) for rendered markdown previews in terminal
